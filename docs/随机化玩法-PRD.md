# 《激流勇进》竞技场 / 怪物模式 · 随机化玩法 PRD

> 版本 v0.2 · 2026-11-16 · 待评审
> v0.2 修订：P3 从「跨技能池随机组合」降级为「本 BOSS 技能**出场顺序**随机」——
> 不需要新骨骼动作、不需要新技能、不需要新美术，工作量从 1~2 天降到 2 小时。
> 工程：`d:\3Dgame - 副本`（Three.js + WebSocket 局域网联机）
> 目标模式：`arena`（潮汐竞技场）、`boss`（怪物模式）
> 本文件只做设计，不含代码改动。确认后再按第五节分阶段实施。

---

## 〇、一句话

给「潮汐竞技场」和「怪物模式」装上**随机性**（全局词缀为核心，局内三选一 / 招式顺序 / 无尽层数为可选层），让同一张图、同一头 BOSS 在第二把、第五把都是不同的局，而不是把 4 个 BOSS 背下来就通关。

**范围控制**：第一版只做词缀（P0+P1，约 2 天）。其余层都是"验证词缀有效之后再说"的选项，不是必须交付。

## 一、现状诊断

### 1.1 两个模式的流程是写死的常量表

| 模式 | 内容来源 | 一局的路径 | 结束后 |
|---|---|---|---|
| 竞技场 | `ARENA_ROUNDS`（`ArenaMode.js` L58） | 固定 3 关：运送 → 擂台 → 决斗，三关两胜 | `#notifyMatchEnd()` 弹结算，无后续 |
| 怪物 | `BOSS_LEVELS`（`bosses.js` L867） | 固定 4 关：深渊火龙 → 炎狱 → 雷霆 → 血魔 | 第 4 关 `#onBossDeath()` → `victory`，无后续 |

两个模式**完成度都很高**（竞技场 2347 行、怪物 6952 行），问题不在内容量，在**排列方式**：第一把是"未知"，第二把起就是"背流程"。

### 1.2 对比道具赛：随机性来自局内，不是内容多

道具赛每把刷出来的道具流不同（`rollItem` 按名次加权 + 20 多件道具），所以同一张地图可以玩很多把。这是**局内变量**，不需要新地图、不需要新美术。

两个目标模式手里已有的素材足够撑起同等量级的随机性：

| 已有素材 | 数量 | 可随机化的方式 |
|---|---|---|
| BOSS | 4 头（`BOSSES`） | 顺序、精英前缀、招式组合、数值缩放 |
| BOSS 技能 | 每头 10~20 个 `skill` | 每局抽 4~6 个组成招式组 |
| 竞技场关卡规则 | 3 套（delivery / ringout / duel） | 顺序随机 + 每关挂词缀 |
| 道具 | 竞速 24 件 / BOSS 14 件 | 掉落权重重排、开局赠送 |
| 天气 | 5 档 | 词缀里复用（雷暴、暴雪、星空） |
| 数值挂点 | `damageScale` / `speedScale` / `cooldownScale` / `hpScale` | 词缀与卡牌全部挂这里 |

**核心工程结论：这是"排列组合 + 一张汇总表"的活，不是做新内容的活。**

### 1.3 为什么现在打完就不玩了

按玩家心理拆，缺的是四件事：

| 缺失 | 玩家内心 | 道具赛为什么有 |
|---|---|---|
| 局内可变 | "这把会不会不一样？" | 道具流随机 |
| 局内成长 | "再打一关我就变强了" | 无（但一局短，不需要） |
| 差一点 | "再来一把就过了" | 有（名次压力） |
| 长期目标 | "还差 3 个解锁" | 无 |

本 PRD 的四层随机性正好一一对应这四点。

## 二、设计总览

```
进局
 ├─ ① 全局词缀：房主抽 1~2 条规则 → 过场卡展示 → 全程生效
 │
 ├─ 逐关循环
 │   ├─ 【可选】关卡/招式随机：本 BOSS 招式顺序洗牌、竞技场关卡顺序、精英前缀
 │   ├─ 打
 │   └─ ② 三选一：通关抽 3 张卡选 1 张 → 立刻生效 → 面板可查
 │
 ├─ ③ 无尽层数：原本打完就结束 → 变成"继续挑战？"（层数递增、词缀累加）
 │
 └─ ④ 结算：星尘（局外货币）→ 解锁新卡 / 新词缀进池 → 回到 ①，池子更大
```

**四层各自的定位**：

| 层 | 解决 | 变化感知 | 实现成本 | 建议批次 |
|---|---|---|---|---|
| ① 词缀 | 每把不一样 | 立刻（过场卡就能看见） | 低 | P0 |
| ② 三选一 | 越打越强 + 构筑欲 | 中（每关一次） | 中 | P2 |
| ③ 招式顺序 / 关卡随机 | 同一关也陌生 | 中（要打起来才发现） | **极低**（1 行遍历 + 一次洗牌） | P3（可选） |
| ④ 无尽 + 解锁 | 差一点 / 长期目标 | 高（有分数可追） | 中 | P4-P5 |

## 三、玩法设计

### 3.1 ① 全局词缀（Modifier）

#### 3.1.1 规则

- 每关进场时抽 **1 条**；从第 3 关起抽 **2 条**（叠加生效）。
- 一局之内不重复；词缀按**强度分层**（轻/中/重），每层抽一条，避免"两条重词缀叠成地狱"。
- 抽定由**房主**执行（单人即本地），随关卡推进广播（复用 `bossStage`，见 4.1）。
- 过场卡上以**两行文案**展示：名称 + 一句话效果，附难度标记（★ / ★★ / ★★★）。

### 3.2 ② 局内三选一（Build / Roguelike 卡牌）

#### 3.2.1 规则

- **触发**：BOSS 每关通关后（`#onBossDeath` 的 `clear` 阶段）、竞技场每关结束后（`#endRound` 的 `roundEnd` 阶段，3 秒回顾期内）。
- **形式**：3 张卡横排，选 1 张，另外 2 张消失（不保留）。10 秒不选自动取第 1 张。
- **生效**：立即写入 `runStats`，下一帧起所有伤害/速度/冷却计算乘进去。
- **清零**：整局结束（通关 / 全灭 / 退出房间）清零；**不发车不清空**，避免误触。
- **可查**：HUD 侧边一个"构筑"按钮，弹出当前已选卡列表（最多 12 张）。

- 每关抽 3 张，**允许重复类别**，但尽量不同类（抽到同类则重掷一次）。

#### 3.2.4 数值汇总表（`runStats`）

所有效果收敛到一张表，伤害计算只读这张表：

```js
runStats = {
  dmgMul: 1,        // 总伤害倍率（火力 + 狂野 + 并肩）
  weakMul: 1,       // 弱点额外倍率
  critChance: 0, critMul: 2,
  takenMul: 1,      // 受伤倍率（防御 + 狂野）
  shieldCdMul: 1, shieldDurAdd: 0,
  turnMul: 1, speedMul: 1, dashCdMul: 1, ramMul: 1,
  itemDmgMul: 1, boxAdd: 0, starterItems: 0, rareOnly: false,
  comboChargeMul: 1, rescueMul: 1, nearbyDmg: 0,
  revive: 0, rewind: 0,
  cards: [],        // 已选卡（用于 HUD 展示与存档）
}
```

**接入点**（不改架构，只在既有乘法点乘一个系数）：
- `BossMode`：`boss.damageScale`（已有）、`#damagePlayer` 里的 `amount`、`#hitBossWithItem` 的结算、`#applySkillTick`
- `ArenaMode`：`#damage(id, dmg, fromId)`、`#weaponHit`、`boat.speedScale/turnRate`
- `Boat`：`speedMul` / `turnMul` / `dashCdMul` 走已有的 `slowTimer` 同款系数位

### 3.3 ③ 招式顺序与关卡随机（v0.2 修订：不做技能跨 BOSS 组合）

> **为什么改方案**：v0.1 写过「从 8~12 个技能池抽 3~5 个」——这个描述不严谨，且会制造
> 不必要的工作量。核对代码后有两条硬事实：
>
> 1. **不需要任何新骨骼动作。** 技能到动画走的是语义映射：`BOSS_SKILLS[skill].anim`
>    → `Boss.#skillAnim()` → `def.anims[语义]` → glb 里已有的 clip。每头 BOSS 自带完整的
>    `anims` 表与 `clipModels`（如深渊火龙：`breath / fd_tail_sweep / fd_rear_roar /
>    fd_rift_slam / fd_gate_call / fd_enrage…`）。不跨 BOSS 挪用技能，现有映射就全部覆盖。
> 2. **技能不能跨 BOSS 混搭。** 每头 BOSS 的 `skills` 数组本来就是量身定做的，且动画映射
>    也只覆盖自己的技能。反例：把炎狱的 `flyDive` 给第一关，第一关没有 `fly` 段，
>    `#skillAnim()` 会 fallback 到 `cast`，读起来就是错的。
>
> 所以改成**只在每头 BOSS 自己的技能列表内打乱出场顺序**：零新资产、零新动画、零 token
> 生成成本，且不存在"技能适不适合这头 BOSS"的问题。

#### 3.3.1 BOSS 招式顺序（改动量：一行遍历）

现状：`Boss.#pickSkill()`（L917）按 `this.def.skills` 的**数组顺序**遍历，取第一个冷却好、
射程合适的技能——同一头 BOSS 每把的出手顺序完全一样。

改为：房主在 `startStage()` 里把这头 BOSS 的 `def.skills` 洗一次牌，得到 `skillOrder`
（用带 seed 的确定性洗牌，随 `bossStage` 广播），`#pickSkill()` 改遍历 `this.skillOrder`。

**所有现存适配判断原样保留，不碰**：

| 已有判断 | 作用 |
|---|---|
| `minHpRatio` | 终盘技能（雷霆棋盘）血量没到阈值就不进池 |
| `reach` 分支 | cone / ring / ground / path / slam / wave / zone 各自的距离适配 |
| `anchored` | 第一阶段站桩时只放能覆盖通道的技能 |
| 贴脸过滤 | wave < 20m、pull/blink < 14m、path < 16m 时不放 |
| `silence` | 沉默期间不起新技能 |

这些判断本来就在做"技能适不适合当前局面"。我们只是换**出场顺序**，不换技能本身，
更不新增技能。第一关只有 4 个技能，洗牌后变化有限——它本来就是教学关，不需要强随机。

#### 3.3.2 精英前缀（可选，P3 之后再评估）

每局第 2 关起，每头 BOSS 有 40% 概率带一个前缀：

| 前缀 | 效果 | 视觉 |
|---|---|---|
| 狂暴的 | 攻速 +25%，血量 -10% | 红色气场 + 眼睛变红 |
| 冰封的 | 每个技能附带 2s 减速 | 蓝白霜雾（复用 blizzard 特效） |
| 贪婪的 | 掉落道具箱 ×1.5，但伤害 +15% | 金色粒子 |
| 腐朽的 | 血量 -25%，但每 20s 无敌 2s | 暗紫色（复用 ink 特效） |

实现上只是改 2~3 个数值 + 挂一个已有特效，无新资产。

#### 3.3.3 竞技场关卡顺序

- 现状：`ARENA_ROUNDS` 固定顺序（第 1 关永远是运送，因为过场卡要写"第 X 关"）。
- 改为：第 1 关固定为 `delivery`（保留教学意义），**第 2、3 关从剩余池里随机抽**。
- 二期再考虑新增 `king`（抢王座）与 `survive`（生存 60s）两种规则，让池子从 2 种变 4 种。

### 3.4 ④ 无尽层数与局外解锁

#### 3.4.1 无尽连战（怪物模式）

- 打完第 4 关（`victory`）不直接结算，弹出选择：**「结束 · 领取奖励」/「继续挑战 · 第 5 层」**。
- 第 5 层起：4 头 BOSS 循环复用，数值按层递增：

```
hp   = base * (1 + 0.35 * (层 - 4))
dmg  = base * (1 + 0.18 * (层 - 4))
词缀数 = min(3, 1 + floor((层 - 1) / 2))
```

- 全灭结束，结算显示 **最高层数**、总伤害、用时、评级。
- 层数记录写 `localStorage`（键 `rr-meta-v1`），主菜单模式卡上显示"最佳：第 N 层"。

#### 3.4.2 竞技场连胜

竞技场是 PvP，不适合做层数。改为**连胜计数**：
- 赢一场 +1，输一场清零。
- 主菜单显示"当前连胜 / 最高连胜"。
- 连胜 3 场起，每场额外抽 1 条**正面词缀**（给玩家"打出手感"的正反馈）。

#### 3.4.3 局外解锁（星尘）

| 项 | 值 |
|---|---|
| 获取 | 每通关 1 层 +10 星尘；全灭时按总伤害额外给（每 1 万伤害 +1）；竞技场每赢 1 场 +8 |
| 用途 | 解锁新卡进池（30/张）、解锁新词缀（50/条）、解锁 BOSS 皮肤（100） |
| 存档 | `localStorage` `rr-meta-v1`，与现有 `rr-settings-v1` 平级 |

**设计原则**：解锁只做"**扩大池子**"，不做"**数值变强**"——否则新玩家会被老玩家碾压。所有解锁项都是"更多选择"，不是"更高数值"。

---

## 四、联机同步方案（最容易翻车的地方）

### 4.1 权威归属

| 数据 | 谁来算 | 为什么 |
|---|---|---|
| 词缀抽取 | **房主** | 各端各抽 = 规则不一致，客机会看到另一套场地 |
| 卡牌候选（3 张） | **房主** 抽，广播给对应玩家 | 防作弊；也保证保底计数一致 |
| 卡牌选择 | **玩家自己**发，房主确认后写进广播 | 保留玩家意志 |
| BOSS 招式组 | **房主** | 招式由房主驱动（现有 `bossCast` 已经这么走） |
| 层数推进 | **房主** | 与现有 `bossStage` 一致 |

### 4.2 新增消息（全部要进 `server/server.js` 的 `RELAY_TYPES`）

| 类型 | 方向 | 载荷 |
|---|---|---|
| `runStart` | 房主 → 全体 | `{ seed, mods: [...], layer: 1 }` |
| `runMod` | 房主 → 全体 | `{ round/stage, mods: [id...] }` |
| `runOffer` | 房主 → 单人 | `{ to, cards: [id, id, id] }` |
| `runPick` | 玩家 → 房主 | `{ id }` |
| `runPickOk` | 房主 → 全体 | `{ who, card, stats: {...} }` |
| `runLayer` | 房主 → 全体 | `{ layer, hpMul, dmgMul }` |

**注意**：`RELAY_TYPES` 是白名单，漏一条 = racing 期间静默丢弃（这个坑之前已经踩过一次）。

### 4.3 断线重连

- 房主 15s 重连缓冲期内，新加入 / 重连的玩家要收一份 `runStart` 全量快照（含当前层数、词缀、已选卡）。
- 客机 UI 只做展示，**不做任何随机**（连"卡牌随机排序"都由房主定）。

## 五、实施阶段与验收

| 阶段 | 内容 | 预估 | 验收标准 |
|---|---|---|---|
| **P0** | 词缀框架 + 怪物 12 条词缀 | 1 天 | 连开 3 把，过场卡词缀各不相同；效果可实测（狂暴时 `cooldownScale=1.3`） |
| **P1** | 竞技场 10 条词缀 + 关卡顺序随机 | 1 天 | 第 2、3 关顺序随机；词缀在 `#startRound` 生效 |
| **P2** | 三选一 UI + 24 张卡 + `runStats` 接入 | 2~3 天 | 选「穿甲弹头」后炮伤实测 ×1.2；12 张卡不溢出 HUD |
| **P3（可选）** | 本 BOSS 招式**顺序**洗牌（不动技能集合、不动动画）+ 精英前缀另议 | **2 小时** | 同一 BOSS 连打 3 把，出招序列至少 2 把不同；`reach/minHpRatio/anchored` 过滤仍生效，不改现有手感 |
| **P4** | 无尽层数 + 最佳纪录 | 1 天 | 第 5 层血量 = 基础 ×1.35；主菜单显示"最佳：第 N 层" |
| **P5** | 星尘与解锁 | 1~2 天 | 局外存档读写正常；解锁后的卡进池 |
| **P6** | 联机全链路 + 回归 | 1~2 天 | 双端词缀一致（逐条对比 toast）；客机选卡后主机 `runStats` 同步；`npm test` PASS |

**建议第一批只做 P0 + P1**（2 天），先验证"词缀能不能显著改变单局体感"，再决定要不要往 P2 投 3 天。

**P3 是另一个极端**：只动 `#pickSkill()` 的一行遍历 + 一次确定性洗牌，**2 小时、零资产、零 token 成本**，
如果想给"招式顺序"也加点变化，可以顺手一起做。它比精英前缀（要挂特效/改数值）更值得先做。

## 六、风险与不做的事

### 6.1 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 词缀互相冲突 | "双核 + 黄金核心 + 加时诅咒"可能让一关 20 秒就结束 | 强度分层抽取（轻/中/重各一），并在过场卡上标注预估时长 |
| 卡牌数值失衡 | +40% 伤害叠 3 层 = 2.2 倍，配狂野可能一枪秒 | 同卡上限 3 层、乘算不叠乘（改为加算再乘） |
| 客机不同步 | 词缀/卡牌如果本地抽，直接裂开 | 全部房主权威，客机零随机 |
| 无尽层数枯燥 | 只是数值放大，玩家会腻 | P4 之后再给高层加"每 5 层换一个地形修饰"（二期） |
| 新手劝退 | 强词缀 + 强 BOSS 叠加 | 前 2 关词缀池只放"轻"档；难度选"普通"时重词缀权重 ×0.5 |

### 6.2 明确不做

- **不做新美术资产**（BOSS、特效、地图一律复用）。
- **不做跨 BOSS 技能组合 / 不生成新骨骼动作**。每头 BOSS 只用自己 `skills` 数组里的技能，
  `anims` 映射已全部覆盖；跨 BOSS 挪用会 fallback 到错误动作。变化的只是**出场顺序**。
- **不做"永久变强"的数值解锁**（只扩大池子）。
- **不改道具赛与竞速**（它们的随机性来源不同，别混进来）。
- **不做联网匹配/匹配池**（现在只有局域网房间，随机性是局内的事）。
