## 0. 先说结论：你标红的两处，不是图没生成，是代码没接上

截图里那两个地方（BOSS 血条左侧徽章、过场大标题左侧图标）显示的其实是 **emoji `🐲`**，
不是任何 png。原因很具体：

| 位置 | 真因 | 状态 |
|---|---|---|
| `#boss-icon`（血条徽章） | `BossMode` 给 UI 的 boss 数据里**漏了 `id` 字段**，`BOSS_ICON[undefined]` 查不到 → 代码回退到 `d.boss.icon`（emoji） | **已修**：补 `id: this.bossDef.id` |
| `#cs-name`（过场大标题） | 这行本来就是字符串拼接 `${data.boss.icon} ${data.boss.name}`，从没走过图标表 | **已修**：改用 `iconImg(BOSS_ICON[data.boss.id])` |

顺带挖出两个"看起来像没换"的隐藏原因，一起修了：

| 问题 | 真因 | 状态 |
|---|---|---|
| 图标偶尔闪一下空白 | `setIcon()` 每次调用都重写 `innerHTML`，而 HUD 每帧都调它 → `<img>` 每帧被销毁重建、反复重新解码 | **已修**：src 没变就只补 class，不动 DOM |
| 就算接上 png 也"看着很糊、像旧的" | `#hud.boss-mode #boss-icon` 上有一条**给 emoji 兜底用的琥珀滤镜**（`grayscale → sepia → saturate(4.5)`），套在彩色龙图上会把整张压成一块黄褐色 | **已修**：`.has-art` 时走原色，只提亮 + 暗投影 |

修完实测（进怪物模式读 DOM）：

```
bossIcon  → <img src="/icons/boss/54_boss_abyss_dragon.png">  loaded: true
cs-name   → <img class="cs-boss-ico" src="/icons/boss/54_boss_abyss_dragon.png"><span>深渊火龙</span>
```

出图：`shots/hud/boss-icon.jpg`（血条徽章，蓝色龙头原色）、`shots/hud/boss-cutscene.jpg`（过场大标题 76px 图标 + 52px 文字）。

也就是说：**BOSS 四张图标（54~57）本来就有，不用再生成。**

## 7. 命名与接入

```
public/icons/
├── avatars/   av_wave.png … av_bot.png        （9）
├── skills/    91_sk_fire.png … 95_sk_blood.png （5）
├── events/    96_ev_boom.png … 103_ev_bind.png （8）
└── ui/        90_ui_crown.png                  （1）
```

`src/ui/icons.js` 里加三张表：

```js
export const AVATAR_ART = {
  wave: '/icons/avatars/av_wave.png', whale: '/icons/avatars/av_whale.png',
  /* … */ bot: '/icons/avatars/av_bot.png',
};
export const SKILL_SRC = { fire: '…', ice: '…', thunder: '…', water: '…', blood: '…' };
export const EVENT_ICON = { boom: '…', enrage: '…', shield: '…', danger: '…',
  melee: '…', heal: '…', core: '…', bind: '…' };
```

头像要注意：`avatarMarkup()` 现在是"自定义图片 → SVG"，接入后改成
"自定义图片 → **png** → SVG 兜底"，这样老存档里的头像 id 不会失效。
